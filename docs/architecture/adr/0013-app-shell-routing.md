# ADR-0013: A small in-house router and command palette for the app shell

**Status:** accepted, 2026-11-28 (Phase 2, item "New app shell").

**Context:** the app needs a product shell: a sidebar with Today, Jobs, Customers, Crew, Materials, Invoices, Reports and Settings, a header search and a command palette on Cmd+K (Ctrl+K on Windows). Until now the renderer was one page with a `view` flag for the components page. The packaged page runs at `tmapp://app/index.html` under a strict CSP, the main process denies every navigation (`will-navigate`), and the packaged security smoke asserts that the page URL never changes. Every later screen will live inside this shell, so the choice has to stay typed and small.

**Chosen:**
* **Routing is typed state, not a URL.** `apps/desktop/src/renderer/shell/routes.ts` lists every screen once (id, label, icon, sidebar placement, summary, palette keywords and, for a screen not built yet, what is coming). `shell/router.ts` is a small store (`get`, `navigate`, `subscribe`) read with React's `useSyncExternalStore`. `RouteId` is a string union, so a wrong screen name is a compile error, and `navigate` also refuses unknown ids at run time. The page URL never changes, so there is no history, hash or path parsing to secure, and the navigation guard and its smoke stay exactly as they were.
* **Last screen per session.** The current screen is kept in `sessionStorage` (`tm.shell.route`): a reload returns to it, a fresh start of the app opens Today. An unknown, missing or unreadable value opens Today. The sidebar's collapsed or expanded choice is a per-computer display preference in `localStorage` (`tm.shell.sidebar`), like the theme; neither is business data, so neither is in SQLite or backups.
* **Focus is part of navigation.** `navigate(route, {focus})` asks for no focus move (a sidebar click keeps focus on the sidebar), the new screen's heading (palette, skip button) or one element by id (palette actions such as New project). The shell moves focus after the screen renders and scrolls the main area to the top on each screen change. The window title names the screen ("Jobs · Electrical T&M").
* **Command palette on the native `<dialog>`** through the design system's `Dialog`, so focus is trapped and Escape closes it. The input is a combobox over a listbox with `aria-activedescendant`; arrows move and wrap, Home and End jump, Enter runs, and focus goes back to where it was. A chosen command runs after the dialog's close event, so a navigation can then move focus to the new screen. The command list is data (`shell/commands.ts`): every screen, the actions that exist today (new project, health check, theme, sidebar, help) and the saved projects, each with an intent the shell carries out. Filtering, ranking, key handling and the Cmd or Ctrl choice are plain functions with unit tests (`tests/unit/app-shell.test.ts`).
* **Header search** is a real labelled input. Typing in it, clicking it or pressing Enter opens the palette with what was typed; it searches screens, actions and projects until phase 3 adds customer, job and invoice search.
* **Screens that hold drafts stay mounted.** Jobs and Settings are hidden, not unmounted, when another screen shows, so a half-typed project or business profile survives a trip to another screen, and a restore still locks every working control at once. Screens not built yet render only while shown, as a designed empty state that says what is coming.
* **Sidebar:** icons with labels, the current screen marked with `aria-current="page"` and an amber bar; below 1200 px it collapses to icons, whose labels stay the buttons' names and show as a flyout on hover or keyboard focus.

**Not chosen:**
* React Router, TanStack Router or wouter: each is a new dependency built around URLs we do not want to change, and their typed-route features need generators or extra packages. Nine screens and no URL need about sixty lines.
* Hash routing (`#/jobs`): changes the page URL that the security smoke pins, and gives back and forward buttons the app does not show.
* A palette library (cmdk, kbar): a new dependency and a second interaction model next to the design system's dialog.

**Consequences:** no new npm dependency. A new screen is one entry in `routes.ts` and one render in `App.tsx`; the sidebar, palette, empty state and tests pick it up. The packaged readiness oracle now expects the shell: the first visible heading is "Today" and the sidebar lists the eight screens in order. That changes the native smoke receipt, so the native proof contract moves from 17 to 18 (`scripts/capture-native-proof.mjs`); the validators keep the old heading for archives of contract 17 and earlier, and contract 18 adds four required cockpit-flow results: the shell opens on Today, every sidebar screen renders, the palette runs a command by keyboard, and it returns focus when closed.
